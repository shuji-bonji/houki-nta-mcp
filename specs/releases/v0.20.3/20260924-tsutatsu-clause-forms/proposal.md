# 変更: nta_get_tsutatsu の clause の形を通達ごとに書き分ける

- 対象: `specs/current/nta_get_tsutatsu/spec.md`（入力の表の `clause` の行）
- 状態: 取り込み済み。実装は v0.20.3（2026-09-24 JST）、`specs/current/` への取り込みも同日
- 起こした日: 2026-09-24（JST）
- 起こした役: Spec Steward

## なぜ変えるか

`clause` の書き方が、仕様・ツールの説明文・実際に受け付ける形の 3 つで揃っていない。LLM はツールの説明文（`tools/list` の応答の `inputSchema.properties.clause.description`）を見て引数を組み立てるので、説明文が実際と違うと、所得税基本通達・相続税法基本通達の番号を消費税法基本通達の形に合わせて作り変えてしまう。

| 書いてある場所 | 今の文面 | 実際との違い |
|---|---|---|
| `specs/current/nta_get_tsutatsu/spec.md` の入力の表 | 「`5-1-9` / `1-4-13の2`（章-節-条）の形」 | 所得税基本通達・相続税法基本通達の番号の形が書かれていない |
| `tools/list` の `clause` の説明文 | 「例: "5-1-9", "11-2-10"（章-項-号 形式）」 | 「章-項-号」はどの通達の番号体系とも違う。所得税基本通達・相続税法基本通達の形も書かれていない |

## 実際に受け付ける形（2026-09-24 に houki-nta-dev で確かめた）

DB から返す経路（SPEC-NTA-GET-TSUTATSU-004）で、次の番号はどれも取得できた。

| 通達 | 番号の形 | 取得できた例 |
|---|---|---|
| 消費税法基本通達 | 章-節-条 | `5-1-9`、`1-4-13の2`、全角の `１－４－１３の２` |
| 法人税基本通達 | 章-節-条（節に枝番号が付くことがある） | `1-3の2-1` |
| 所得税基本通達 | 条-項。複数の条に共通する通達は「条~条共-項」 | `34-1`、`2-4の2`、`23~35共-6`（`23〜35共-6` でも取れる） |
| 相続税法基本通達 | 条-項。複数の条に共通する通達は「条・条共-項」 | `1の3・1の4共-1`（`3-1` は DB の番号一覧で確認） |

国税庁サイトから取る経路（SPEC-NTA-GET-TSUTATSU-008）が受け付けるのは、今の仕様どおり「章-節-条」（条の枝番号まで）だけである。

## 何を変えるか

1. 仕様: 入力の表の `clause` の行を、通達ごとの形と例を書いた文面にする（差分は `specs/nta_get_tsutatsu/spec.md`）。ID の付いた振る舞いは変えない
2. 実装（承認後に Coder が行う）: `tools/list` の `clause` の説明文を、1 の文面に合わせる。振る舞い・エラー・テストの期待値は変えない

## この差分に含めないが、確かめる中で見つけたこと

別の差分にするか、`spec.md` の「未決」に足すかを人が決める。

- **SPEC-NTA-GET-TSUTATSU-006 の「DB に無い基本通達 4 種は国税庁サイトから取る」は、実際には消費税法基本通達でしか成り立たない見込み。** 国税庁サイトから取る経路は、番号を「章-節-条」に限り（008）、ページの URL を `{章}/{節}.htm` の形で組み立てる。所得税基本通達・相続税法基本通達の番号は「条-項」なので 008 の `INVALID_ARGUMENT` になる。法人税基本通達はページの URL が `01/01_03_02.htm` のような別の形なので、組み立てた URL では取れない見込み（`docs/DESIGN.md` の「Phase 1d 調査結果」の表とも一致する）。4 通達とも DB に入っている今の環境では、この経路は通らないので実際には確かめていない。
