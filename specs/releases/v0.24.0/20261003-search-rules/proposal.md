3 件とも、検索ツールの応答が「実際にしたこと」と違って読める、または同じ語の書き方で結果が変わる問題である。

## Issue ごとの変更

### #81 英字の大文字と小文字

**今の動き（v0.23.0）**: `keyword` は英字を小文字に寄せ（SPEC-NTA-SEARCH-RULES-008）、DB の本文は大文字のまま（007）。全文検索と、2 文字の語だけのときの部分一致（SQLite の `LIKE`）は大文字と小文字を区別しないので当たる。3 文字以上の語と混ざるときの 2 文字の語の絞り込み（004）だけが、JS の文字列の比較で区別するため、`"QR コード"` が 0 件になる。2 文字の語だけのときの `snippet` も、語の位置を区別して探すので、本文に大文字でしか無いと `<b>` が付かない。`search_notes` と `scoreReasons` の語は小文字に寄せた表記。

**変えた後の動き**: どの探し方でも大文字と小文字を区別しない（021）。`snippet` の `<b>` の位置も区別せずに探す（003）。`search_notes` と `scoreReasons` の語は、渡した表記を半角に揃えたもので、大文字と小文字は渡したまま（006）。

| 種類     | 仕様 ID                             |
| -------- | ----------------------------------- |
| ADDED    | SPEC-NTA-SEARCH-RULES-021           |
| MODIFIED | SPEC-NTA-SEARCH-RULES-003・004・006 |

| 決めること                                                                          | 答え                                                                                                                          |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 004 の絞り込みで大文字と小文字を区別しないようにするか（不具合として直すか）        | 不具合として直す（021・004）。全文検索と部分一致はすでに区別していないので、絞り込みだけを揃える                              |
| `search_notes` に表示する語を、渡した表記にするか、小文字に寄せた表記のままにするか | 渡した表記（半角に揃えたもの）にする（006）。`"DX"` を渡して `"dx"` と返ると、利用者（LLM）が別の語を探したと読むおそれがある |

### #80 3 文字未満の略称

**今の動き（v0.23.0）**: `keyword` 全体が略称で、略称が 3 文字未満のときは、正式名だけを全文検索し、略称そのものは探さない。正式名も 3 文字未満（`民`→`民法`・`商`→`商法`・`刑`→`刑法`）のときは、正式名も探せず、略称は 1 文字なので外され、常に 0 件になる。`search_notes` は `keyword` の長さだけで決まり、2 文字の略称では「部分一致 (LIKE) で検索しました」、1 文字の略称では「1 文字のため検索条件から外しました」になる。

**変えた後の動き**: 元の語と正式名を、それぞれの長さで全文検索（3 文字以上）か部分一致（2 文字）で探し、1 文字の語は使わず、結果を合わせる（009）。`search_notes` は実際の探し方を書く文にする（006）。

| 種類     | 仕様 ID                        |
| -------- | ------------------------------ |
| MODIFIED | SPEC-NTA-SEARCH-RULES-006・009 |

| 決めること                                                                                                   | 答え                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 3 文字未満の略称でも元の語を部分一致で探して正式名の全文検索と合わせるか、正式名だけで探すことを意図とするか | 合わせる（009 の本文どおり）。正式名だけにすると、本文に略称だけを書いた文書（国税庁の資料は「消法」「措法」と書くことが多い）が返らない |
| 意図とするなら `search_notes` の文を直し、009 に例外を書く                                                   | 意図としないので例外は書かない。`search_notes` の文は実際の探し方に合わせて直す（006）                                                   |

### #72 `nta_search_qa` の `domain`

**今の動き（v0.23.0）**: inputSchema の `domain` は houki-abbreviations の分野の一覧（`tax`・`labor`・`accounting`・`commercial`・`civil`・`administrative`）の列挙。`tax` は絞り込まず（SPEC-NTA-SEARCH-QA-003）、それ以外は DB を開かずに `results: []` と `hint`（002）。DB を開かないので、DB に事例が 1 件も無くても `DOC_NOT_FOUND`（001）にならず、`freshness` も付かない。

**変えた後の動き**: `domain` を inputSchema から外す。渡すと、どの値でも `INVALID_ARGUMENT`（010）。`domain` を省いた呼び出しの結果は変わらない（0.22.0 で `tax` は絞り込まない形にしたので、`domain: "tax"` を付けていた呼び出しも、外せば同じ結果になる）。応答に `domain` のフィールドは無いので、T4（フィールドを消さない）には当たらない。

| REMOVED | SPEC-NTA-SEARCH-QA-002・003 |

| 決めること                                           | 答え                                                                     |

| `domain` を残すか、`topic` に一本化するか            | `topic` に一本化する（勧める案 A。`domain` を外す）                      |
| 残すなら、`tax` 以外のときにも DB の有無を確かめるか | 外すので当たらない（案 B を採るなら確かめる。下の「人が判断すること」3） |

## 人が判断すること

1. **（#81）`search_notes` の語の表記。** 渡した表記を半角に揃えたもの（大文字と小文字は渡したまま）にした。小文字に寄せたままにする案もあるが、利用者が渡していない表記が返るので勧めない。`scoreReasons` も同じ表記にした。
2. **（#80）1 文字の略称（`民`・`商`・`刑`）も正式名の部分一致で探すこと。** Issue が名指ししたのは 2 文字の略称（`消法`）だが、「元の語と正式名を、それぞれの長さで探す」という 1 つの規則にすると、1 文字の略称で正式名が 2 文字のものも探すことになる。これらは今は常に 0 件で、変えると「民法」を含む文書が多く当たる見込み（件数は確かめていない）。1 文字の略称は今のまま（`破`・`憲` は正式名の全文検索、`民`・`商`・`刑` は 0 件）にする案もあり、その場合は 009 に「略称が 1 文字で正式名が 3 文字未満なら探さない」と書く。
3. **（#72）`domain` を外すこと（案 A）。** 外す側で書いた。残す案（案 B: 今の動きを仕様に書き、`tax` 以外のときも DB の有無を確かめて `DOC_NOT_FOUND` を返す）は、houki-egov-mcp 0.18.0（#55）と `nta_search_tsutatsu` が `domain` を受け付けない中で、`nta_search_qa` だけが受け付けることになる。B を採る理由があるとすれば「呼び出し側が `domain: "tax"` を付ける癖を持っていても失敗しない」ことだが、houki-research-skill と houki-hub の呼び出し例には `nta_search_qa` に `domain` を渡す例が無い。A で今まで通っていた `domain` 付きの呼び出しは `INVALID_ARGUMENT` になり、`next_actions` の `list_tools` で inputSchema を確かめるよう案内される（SPEC-NTA-COMMON-ERRORS-007）。
4. **承認日。** この proposal.md に承認日と PR 番号を書く。
