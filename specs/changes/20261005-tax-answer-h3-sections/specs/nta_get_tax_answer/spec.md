## MODIFIED

### SPEC-NTA-GET-TAX-ANSWER-007 markdown（既定）の応答

`format` を省くか `markdown` にしたとき、応答は次を含む文字列である。DB から返したときも国税庁サイトから取ったときも同じ形。

- 見出し `# No.<番号> <題名>`（例: `# No.6101 消費税の基本的なしくみ`）
- `> 法令時点: <ページに書かれた時点>`（例: `> 法令時点: 令和8年4月1日現在法令等`）と `> 対象税目: <税目>`（例: `> 対象税目: 消費税`）の行。ページに無いものは出さない
- 節（SPEC-NTA-GET-TAX-ANSWER-019）ごとに、見出しの行とその段落。見出しの行は、`level` が 2 の節（ページの h2）は `## <見出し>`、`level` が 3 の節（ページの h3）は `### <見出し>`。段落の無い節（019 の、次の見出しが h3 の h2 の節）は見出しの行だけを出す。「対象税目」の見出しは節にせず、上の `> 対象税目:` の行にする
- `出典: <国税庁ページの URL>`・`取得: <取得日時>`・`取得元: <ローカル DB（bulk download で取り込んだもの）| 国税庁サイト（この呼び出しで取得）>`
- タックスアンサーの位置付けの注（国税庁の参考解説資料で法的拘束力はなく、実務判断は通達・法令本文に基づく必要があること）

例（2026-10-05 JST の No.6101。「消費税の負担者」から「納税事務の負担軽減措置等」までの 4 つはページでは「概要」の下の h3）: 見出しの行は、上から `## 概要`・`### 消費税の負担者`・`### 課税のしくみ`・`### 申告・納付`・`### 納税事務の負担軽減措置等`・`## 根拠法令等`・`## 関連リンク` の 7 行になる（v0.25.0 では `## 概要`・`## 根拠法令等`・`## 関連リンク` の 3 行で、h3 の 4 つの段落は `## 概要` の下に続いた）。

### SPEC-NTA-GET-TAX-ANSWER-008 json の応答

`format` を `json` にしたとき、応答は次のフィールドを持つ。値の無いフィールドは `null` にし、キーは無くさない。

| フィールド                                    | 内容                                                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `taxAnswer.no`                                | 記事番号。引数の `no`（前後の空白を除いたもの。SPEC-NTA-GET-TAX-ANSWER-011）。例: `"1120"`          |
| `taxAnswer.title`                             | 題名。例: `"医療費を支払ったとき（医療費控除）"`                                                    |
| `taxAnswer.effectiveDate`                     | ページに書かれた法令時点の文字列。例: `"令和7年4月1日現在法令等"`。無いときは `null`                |
| `taxAnswer.basisDate`                         | `effectiveDate` から読んだ日付（`YYYY-MM-DD`）。例: `"2025-04-01"`。`effectiveDate` が `null` か、日付を読めないときは `null`。検索の `results[].basisDate`（SPEC-NTA-SEARCH-RULES-015）と同じ値 |
| `taxAnswer.taxCategory`                       | 対象税目。例: `"消費税"`。無いときは `null`                                                         |
| `taxAnswer.sections`                          | 節の配列。節の分け方と並べ方は SPEC-NTA-GET-TAX-ANSWER-019。要素は `heading`（見出し）、`paragraphs`（段落の文字列の配列）、`level`（ページの見出しの段。h2 は `2`、h3 は `3`）の 3 つのキーを持つ。配列は 1 件以上ある。`paragraphs` が空の要素は、019 の「次の見出しが h3 の h2」の節だけ |
| `taxAnswer.sourceUrl` / `taxAnswer.fetchedAt` | 出典 URL と取得日時                                                                                 |
| `index_status` / `orphaned_at` / `notice`     | SPEC-NTA-GET-TAX-ANSWER-009。索引にある記事と、この呼び出しで国税庁サイトから取った記事では `null`  |
| `source`                                      | `db` または `live`                                                                                  |
| `legal_status`                                | `binds_citizens: false` / `binds_courts: false` / `binds_tax_office: false` と注                    |

日付の読み方は、和暦の「<元号><年>年<月>月<日>日」を西暦の `YYYY-MM-DD` にする（元年は 1 年）。DB の経路でも国税庁サイトの経路でも同じ読み方で、bulk download が DB の発出日の列に入れる値と同じになる。

例: 法令時点が `令和7年4月1日現在法令等` の記事は `taxAnswer.effectiveDate: "令和7年4月1日現在法令等"`・`taxAnswer.basisDate: "2025-04-01"`。法令時点の書かれていない記事は `taxAnswer.effectiveDate: null`・`taxAnswer.basisDate: null`（v0.22.0 では `effectiveDate` のキーが無く、`basisDate` は無かった）。`taxAnswer.sections` の要素は、v0.25.0 では `heading` と `paragraphs` の 2 つのキーで、`level` は無かった。

## ADDED

### SPEC-NTA-GET-TAX-ANSWER-019 ページの見出し h2 と h3 をどちらも節の区切りにし、節ごとに見出しの段を `level` で返す

記事のページの本文の見出し h2 と h3 のそれぞれで節を切り、`taxAnswer.sections`（SPEC-NTA-GET-TAX-ANSWER-008）に次のとおり入れる。

- 節の段落は、その見出しの次から、次の h2 か h3 の前までの段落である。h3 の段落は、その上の h2 の節には入れない
- 節は、見出しがページに現れる順に、1 つの配列に並べる。h3 の節を h2 の節の中に入れ子にしない。各節の `level` は、h2 の節が `2`、h3 の節が `3` である。h3 の節がどの h2 の節の下にあるかは、配列の中でその h3 の節より前にある、最も近い `level: 2` の節で分かる
- 段落が 1 つも無い節は作らない。ただし、h2 の次の見出しが h3 のとき（h2 の直後に段落が無く、すぐ小見出しが続くとき）は、その h2 の節を `paragraphs: []`・`level: 2` で作る。h2 の見出しの文字列を残すためである
- 「対象税目」の h2 は節にせず、`taxAnswer.taxCategory` にする（今のまま）。「サイトマップ」「お問い合わせ先」で始まる見出しは、h2 でも h3 でも節にしない
- h4 以下の見出しは、節の区切りにも段落にもしない（今のまま）
- 節の分け方と `level` は、国税庁サイトから取ったとき（SPEC-NTA-GET-TAX-ANSWER-005）、取った記事を DB に書き戻した後に DB から返すとき（SPEC-NTA-GET-TAX-ANSWER-006）、`--bulk-download-tax-answer` で入れた行を DB から返すとき（SPEC-NTA-GET-TAX-ANSWER-004）のどれでも同じである
- v0.25.0 以前に DB に入れた行の節は `level` を持たない。その節はすべて h2 の見出しで切ったものなので、DB から返すときは `level: 2` を入れて返す。その行の節の分け方は、入れ直すまで v0.25.0 以前のまま（h3 の見出しは無く、h3 の段落は上の h2 の節に入っている）。入れ直し方は CHANGELOG 0.25.1 に書く
