## なぜ変えるか

DB に通達が入っていない利用者が、基本通達 4 種の条項を 1 回の呼び出しで取れるようにするためです。いまの仕様と実装には、次の 2 つの問題があります。

1. **国税庁サイトから取れるのは消費税法基本通達だけ。** 仕様 SPEC-NTA-GET-TSUTATSU-006 は 4 通達を国税庁サイトから取るとしているが、実装は番号を「章-節-条」に限り、ページの URL を `{章}/{節}.htm` で組み立てる。この前提が成り立つのは消費税法基本通達だけで、法人税基本通達は存在しない URL を取りに行って `SOURCE_API_ERROR`（`retryable: true`）、所得税・相続税法基本通達は `INVALID_ARGUMENT` になる（#54 の再現表）
2. **一度取得すると、同じ通達の他の節が取れなくなる。** 国税庁サイトから取った 1 節分を DB に書き戻すと、SPEC-NTA-GET-TSUTATSU-005 の「DB に通達はあるが条項が無い」に当たり、他の節の条項は国税庁サイトへ進まずに `ARTICLE_NOT_FOUND` になる。消費税法基本通達でも起きる（2026-09-25 に v0.20.3 と実際の国税庁サイトで、消基通 `5-1-9` を取った後の `1-4-1` で確認）

## 変わる振る舞い

- 基本通達 4 種は、DB に無い条項を国税庁サイトから取る。消費税法基本通達以外は、目次ページから条項の載っていそうなページを選び、順に取得する（006）
- DB の経路で `ARTICLE_NOT_FOUND` を返すのは、その通達を bulk download で全節取り込んだときだけ。書き戻しの分しか無い通達は国税庁サイトへ進む（005）
- 番号の形の検査を通達ごとの形に合わせ、`hint` にその通達の番号の形と例を入れる（008）
- `SOURCE_API_ERROR` は目次・ページの取得の失敗だけに出す。組み立てた URL が存在しないことでは出さない（009）
- 候補ページのどれにも条項が無いとき、見たページの番号と URL を返す（010）
- 目次を DB に保存して使い回し、条項が見つからないときにだけ取り直す（014、新規）
- 1 回の呼び出しで取るページは 10 までにする（015、新規）
- 国税庁サイトから取る経路でも、`clause` の全角の数字・ハイフンを半角に揃える（入力の表、未決 1 の解消）

## 変わらない振る舞い

- 略称解決、管轄の判定、`clause` が無いときのエラー（001〜003）
- DB に条項があるときに DB から返すこと（004）
- 基本通達 4 種以外で DB に無い通達の `TSUTATSU_NOT_FOUND`（007）
- markdown / json の応答の形、`base_laws` と `next_actions`（011〜013）

## 対象外

- 基本通達 4 種以外の通達（電帳法取通など）を国税庁サイトから取ること
- 書き戻した条項の内容が古くなったときの更新（bulk download の `--refresh` の役目のまま）
- 目次の世代移行（`sozoku` → `sozoku2` のようなルート URL の変更）への自動追随。ルート URL はコード側で変える
